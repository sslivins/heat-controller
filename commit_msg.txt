Fix coverage.py greenlet tracing gap causing false CI coverage failures

pytest-cov/coverage.py doesn't trace across greenlet context switches by
default. SQLAlchemy's async engine uses greenlet internally to bridge
async/sync execution, so on CI's Linux+uvloop combo, code paths inside
route handlers that touch the DB (i.e. most of devices.py/schedule.py/
tags.py) were silently excluded from coverage even though the tests
genuinely exercised them (53 passed both times). Adding
concurrency = ["greenlet", "thread"] to [tool.coverage.run] fixes
attribution across greenlet switches.

Revert the temporary -v pytest flag used to rule out a test-discovery
issue (all 53 tests were confirmed running and passing in CI).
